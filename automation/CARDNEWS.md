## 1. 오늘의 목적지

아래 10개에서 UTC 기준 오늘 날짜의 연중 일수를 10으로 나눈 나머지를 인덱스로 쓴다.

```
['jeju','osaka','tokyo','bangkok','danang','chiangmai','paris','switzerland','bali','hawaii']
```

`date -u +%j` 로 연중 일수를 구한다(앞의 0은 무시하고 정수로).

## 2. 데이터는 스크립트가 찾는다

**직접 조회하지 않는다.** `generate-daily-card.js` 가 그날 쓸 영상을 스스로 고른다(사이트와 같은 정렬 — 제품 있는 영상 우선, 그다음 조회수). Supabase 가 막히면 저장소의 정적 페이지에서 같은 값을 읽는 폴백이 들어있다.

실행하면 아래 JSON 이 나온다. **캡션에 쓸 값은 전부 여기서 가져올 것** — 카드에 나온 영상과 캡션 링크가 어긋나지 않게 하기 위함이다.

```json
{ "file": "...", "destination": "오사카", "youtube_id": "AtrVvqPm-XQ",
  "views_man": 477, "product_count": 3, "title": "...", "channel": "..." }
```

카피를 쓰려면 영상이 뭘 다루는지 알아야 하니, `js/video-notes.js` 에서 그 `youtube_id` 의 소개문구를 읽는다. 필요하면 `watch/<youtube_id>/index.html` 의 `product-name` 들도 본다.

## 3. 카피 쓰기 — 여기가 제일 중요하다

카드에 들어가는 건 네 덩이다.

| 자리 | 성격 | 분량 |
|---|---|---|
| 배지 | 라임 알약. 짧은 한마디 | 5~9자 |
| 헤드라인 | 카드의 얼굴. 줄바꿈을 직접 정한다 | **2~3줄**, 한 줄 7자 안팎 |
| 보조문구 | 헤드라인을 받아주는 설명 | 2줄 |
| 푸터 | 사이트에 뭐가 있는지 | 12~16자 |

**목적지 이름은 헤드라인에 쓰지 않는다(2026-08-10).** 스크립트가 라임색 첫 줄로 자동으로 붙인다 — `오사카` / `돈키호테 가서` / `이걸 안 사면` / `후회한다는데` 처럼 된다. 카피에 `오사카`를 또 쓰면 두 번 나온다. 헤더 오른쪽에 있던 `08.10 오사카` 라벨은 없앴다(같은 정보가 두 곳에 있을 이유가 없고, 날짜는 피드에서 쓸모가 없다).

목적지 줄이 자동으로 붙으므로 **카피 헤드라인이 3줄이면 카드에는 4줄이 된다.** 4줄까지는 들어가지만, 목적지 이름이 긴 곳(치앙마이·싱가포르·오키나와)은 2줄로 쓰는 게 안전하다.

### 사람이 쓴 것처럼

이게 이 카드의 성패를 가른다. 광고 문구처럼 읽히면 그냥 넘긴다.

- **말하듯 끝낸다.** `~더라고요`, `~는데`, `~대요`, `~한다는데` 처럼 대화체 종결을 쓴다. `~합니다`, `~하세요`, `~해보세요` 같은 안내문 말투는 쓰지 않는다.
- **문장을 끝까지 닫지 않아도 된다.** `돈키호테 가서 / 이걸 안 사면 / 후회한다는데` 처럼 말끝을 흐리면 나머지가 궁금해진다.
- **군더더기를 조금 남긴다.** `하필`, `괜히`, `또`, `진짜` 같은 말이 한 개쯤 있으면 사람 말이 된다. 다 덜어낸 문장은 광고처럼 읽힌다.
- **딱 떨어지는 대구·라임을 피한다.** `A도 되고 B도 되는` 식의 정돈된 대구는 AI 티가 난다.
- **이모지 금지.** 디자인 원칙이다(카드에 이모지가 한 개도 없다).
- **감탄사로 시작하지 않는다.** `여행 갈 때 필수템!` 류는 쓰지 않는다.

### 사실 관계

- **제품을 특정하지 말 것.** 썸네일에 그 영상의 어떤 아이템이 찍혔는지는 코드가 알 수 없다. `승무원이 7년째 쓰는 그 캐리어` 라고 썼다가 사진은 화장품 소분 용기였던 적이 있다. **`?` 가 가린 게 무엇이든 문장이 성립하게** 쓴다 — 영상 단위로(`전직 승무원이 꼽은 여행꿀템 3가지`) 또는 카테고리 단위로(`하필 다 약이더라고요`).
- **확인 못 한 건 쓰지 않는다.** 가격 비교(`한국보다 싸다`), 댓글 반응, `제일 많이`·`1위` 같은 순위 표현은 근거가 없으면 쓰지 않는다. 조회수·채널명·아이템 개수는 위 JSON 의 실제 값이다.
- **개수는 `product_count` 를 쓴다.** 영상 제목의 "3가지"와 우리가 정리한 개수가 다를 수 있다.
- **조회수 숫자를 카피에 또 넣지 않는다.** 카드 하단에 큰 숫자로 이미 있다 — 배지나 보조문구에 `477만이 본` 을 넣으면 같은 숫자가 두 번 나온다.
- **판매·구매 유도 금지.** `구매처 확인하세요`, `사세요` 안 쓴다. 원작자 수익을 가로채는 느낌을 주지 않기 위한 원칙이라 꼭 지킨다. 푸터는 `정리해뒀어요` 처럼 있는 사실만 알린다.

### 채널별 캡션

**모든 채널 공통**

- 실제 조회수를 넣어 신뢰도를 준다.
- 구매 유도 금지(위와 같은 이유).
- **링크는 홈이 아니라 그 영상 페이지로 건다.** `https://shortsbox.kr/watch/<youtube_id>/?utm_source=<채널>&utm_medium=social` (끝 슬래시 뒤에 쿼리스트링). `youtube_id` 는 2장 JSON 의 값.

**3-1. 스레드** (2~4문장) — 승인 시 이 텍스트가 그대로 게시된다. `pending-post.json` 의 `threads_text`.
캐주얼한 후킹으로 시작, `utm_source=threads` 링크 포함, 이모지 1~2개, 500자 이내.
(캡션에는 이모지를 써도 된다. 금지는 카드 이미지 안에서만.)

**3-2. 인스타그램** (2~4문장 + 해시태그 줄)
raw URL 을 쓰지 않는다(인스타는 캡션 링크가 안 눌린다). 마지막 줄은 `🔗 프로필 링크에서 확인해보세요`. 해시태그 5~8개를 별도 줄로.

**3-3. X** (1~2문장) — 더 짧고 위트있게, 반말 섞은 구어체 허용. `utm_source=x`. 이모지 1개.

**3-4. 카카오톡 오픈채팅** (2~3줄) — 친구한테 톡 보내듯. `utm_source=kakao`. 이모지 1~2개.

**3-5. 디시인사이드 여행갤러리** (제목 + 본문 분리)
제목은 질문형이나 `~함?ㅋㅋ` 같은 디시 톤. 본문 2~3문장 반말. `utm_source=dcinside`. 광고 냄새 나면 삭제·제재 대상이니 "그냥 발견한 정보 공유하는 유저" 느낌으로. 최종 보고에 `디시 갤러리는 규정상 삭제·제재될 수 있으니 처음 몇 번은 직접 확인하며 올리는 걸 권장` 한 줄 포함.

## 4. 카드 이미지 생성

먼저 `npm install`. `node_modules` 는 커밋돼 있지 않아 매번 새로 받아야 한다(`@napi-rs/canvas`).

```bash
node scripts/generate-daily-card.js <slug> \
  --badge "이게 뭐길래" \
  --headline "돈키호테 가서|이걸 안 사면|후회한다는데" \
  --sub "무조건 사와야 한다는 게|하필 다 약이더라고요." \
  --foot "어떤 약인지 정리해뒀어요"
```

줄바꿈은 `|` 로 직접 넣는다. 자동 줄바꿈을 쓰지 않는 이유는 기계가 어절로 끊으면 `약부터 / 담으라는 이유` 처럼 줄 길이가 들쭉날쭉해지기 때문이다. **줄 길이를 눈으로 맞춰서 쓸 것.**

결과: `assets/card-news/daily-<slug>-<YYYY-MM-DD>.png` (UTC 기준), 1080×1350.

폰트는 `scripts/vendor-fonts/` 에 들어있다(Paperlogy 2종·Anton·IBM Plex Mono·Pretendard 2종). 시스템 폰트나 CDN 에 의존하지 않으므로 예전의 "이모지가 빈 네모로 나옴" 류 패치는 더 필요 없다.

**카피가 자리를 넘치면 스크립트가 종료코드 1로 멈추고 파일을 만들지 않는다.** 어느 줄이 몇 px 넘쳤는지 찍어주니 줄바꿈을 고쳐 다시 실행할 것. 무인 실행이라 조용히 잘리면 아무도 모른다.

## 5. 헬스체크

PNG 가 실제로 생겼고 0바이트가 아닌지 확인하고, **Read 로 열어서 눈으로 본다.** 볼 것:

- 헤드라인·보조문구가 잘리거나 겹치지 않았는지
- 블러된 사진이 그날 영상의 것인지(왼쪽 아래 형태로 짐작 가능)
- 같은 숫자가 두 번 나오지 않았는지

실패했으면 이후 단계(커밋·텔레그램)를 전부 건너뛰고 최종 보고 첫 줄에 `⚠️ 실패` 를 크게 적고 어느 단계에서 무슨 에러인지 정확히 쓴다. **절대 실패를 성공처럼 보고하지 않는다.**

## 6. 커밋

이미지가 공개 URL로 접근돼야 스레드 게시가 된다. 그래서 반드시 커밋한다.

```bash
git config user.email "noreply@anthropic.com"
git config user.name "shortsbox cardnews"
git add assets/card-news/daily-<slug>-<날짜>.png automation/pending-post.json
git commit -m "카드뉴스 자동 생성 및 게시 대기 (날짜)"
git push
```

> **개인 토큰(PAT)을 쓰지 마라.** GitHub 쓰기는 **Claude GitHub App** 이 담당한다. PAT 는 어떤 URL 형식으로도 403 이고 REST Contents API 와 GitHub MCP 도 같다. 읽기만 통과한다.

push 가 거부되면 `git pull --rebase` 후 한 번만 재시도한다.

push 후 1~2분이면 `https://www.shortsbox.kr/assets/card-news/daily-<slug>-<날짜>.png` 로 공개된다.

**`image_url` 은 반드시 `www.` 를 붙인다.** non-www 는 308 로 www 로 넘기는데, 스레드가 이미지를 내려받을 때 리다이렉트를 한 번 더 타게 만들 이유가 없다. 캡션의 UTM 링크는 리다이렉트로 쿼리스트링이 보존되므로 기존 형태를 유지해도 되지만, 이미지는 페처가 직접 받아야 하므로 최종 주소를 그대로 준다.

`pending-post.json` 구조:

```json
{
  "status": "pending",
  "date": "YYYY-MM-DD",
  "destination_slug": "<slug>",
  "destination_name": "<이모지+이름, 예: 🥐 파리>",
  "youtube_id": "<2장 JSON 의 youtube_id>",
  "headline": "<헤드라인 (| 를 공백으로 바꿔 한 줄로)>",
  "subline": "<보조문구>",
  "image_path": "assets/card-news/daily-<slug>-<날짜>.png",
  "image_url": "https://www.shortsbox.kr/assets/card-news/daily-<slug>-<날짜>.png",
  "threads_text": "<3-1 스레드 캡션 전문>",
  "captions": {
    "threads": "<3-1 전문 — threads_text 와 같은 값>",
    "instagram": "<3-2 전문, 해시태그 줄 포함>",
    "x": "<3-3 전문>",
    "kakao": "<3-4 전문>",
    "dcinside_title": "<3-5 제목>",
    "dcinside_body": "<3-5 본문>"
  },
  "telegram_anchor_message_id": null,
  "reminded_at": null,
  "last_error": null,
  "last_error_at": null,
  "last_update_id": null,
  "attempt_count": 0
}
```

## 7. 텔레그램 전송 — 버튼을 단다

`$TELEGRAM_BOT_TOKEN`, `$TELEGRAM_CHAT_ID` 를 쓴다. 비어 있으면 이 단계를 건너뛰고 보고에 적는다.

### 7-1. 카드 + 승인/거부 버튼

**누르지 않으면 게시되지 않는다.** ✔ 가 게시의 전제다. 3시간 넘게 안 누르면 게시 루틴이 한 번 상기시켜준다(`APPROVE.md` 4장).

```bash
curl -s -X POST "https://api.telegram.org/bot$TELEGRAM_BOT_TOKEN/sendPhoto" \
  -F chat_id="$TELEGRAM_CHAT_ID" \
  -F photo=@<PNG 경로> \
  -F caption="오늘의 목적지: <이모지+이름> — 쇼츠박스 카드뉴스

✔ 를 누르면 스레드에 게시합니다.
누르지 않으면 올라가지 않습니다." \
  -F reply_markup='{"inline_keyboard":[[{"text":"✔ 스레드에 게시","callback_data":"sb_approve"},{"text":"✖ 오늘은 건너뛰기","callback_data":"sb_reject"}]]}'
```

응답의 `result.message_id` 를 **반드시 기록**한다(python3 로 JSON 파싱 권장). 이걸 `pending-post.json` 의 `telegram_anchor_message_id` 에 채워 넣고 다시 커밋·push 한다.

**이 message_id 가 핵심이다.** 게시 루틴이 "어느 카드에 대한 승인인지"를 이걸로 판단한다 — 어제 카드의 버튼을 오늘 카드의 승인으로 잘못 읽으면 승인 안 받은 게시가 된다. 기록에 실패하면 `telegram_anchor_message_id` 가 `null` 로 남고, 게시 루틴이 다음 주기에 승인 카드를 다시 보낸다(`APPROVE.md` 5장).

### 7-2. 채널별 캡션 전송

**5개 채널 캡션을 `pending-post.json` 의 `captions` 에 반드시 저장한다(2026-08-11 추가).**
예전에는 최종 보고서에만 있어서 세션이 끝나면 사라졌고, 사용자가 폰에서 복사할 방법이
스레드용 하나뿐이었다. 저장해두면 나중에 어느 루틴에서든 다시 보낼 수 있다.

8번 최종 보고와 같은 텍스트를 저장소 밖 임시 디렉토리에 파일로 쓰고 그대로 보낸다.

```bash
curl -s -X POST "https://api.telegram.org/bot$TELEGRAM_BOT_TOKEN/sendMessage" \
  -F chat_id="$TELEGRAM_CHAT_ID" -F text=<캡션모음.txt
```

각 응답이 `{"ok":true` 인지 확인한다. 실패하면 보고에 에러를 정확히 남긴다.

### 7-3. SendUserFile

생성된 PNG 를 `status: "proactive"` 로 사용자에게 전달한다.

## 8. 최종 보고

사용자가 바로 복사해 쓸 수 있게 채널별로 구분해서 남긴다.

- 오늘의 목적지 + 카드에 쓴 영상(채널명·조회수)
- 이미지 전달 사실 + `텔레그램 카드의 ✔ 를 누르면 스레드에 올라갑니다. 누르지 않으면 올라가지 않습니다` 안내
- **[스레드용]** 캡션 전문 (utm_source=threads)
- **[인스타그램용]** 캡션 + 해시태그 (프로필 링크 안내 포함)
- **[X용]** 캡션 전문 (utm_source=x)
- **[카카오톡용]** 캡션 전문 (utm_source=kakao)
- **[디시인사이드용]** 제목 + 본문 (utm_source=dcinside) + 규정 확인 권장 한 줄

한국어로 작업한다.
